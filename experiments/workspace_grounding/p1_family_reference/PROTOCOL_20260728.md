# Workspace grounding P1：全 reference 对称 family 标注协议

协议版本：`workspace-grounding-p1-family-reference-v1-20260728`

## 1. 目标

P0 只重新标注了四条路由漏检，不能据此对 30 条既有
reviewed-positive 计算对称的 family-conditioned recall。

P1 对冻结 holdout 中全部 30 条既有 reviewed-positive 使用同一独立模型、
同一字段和同一证据边界重新标注，回答：

1. 哪些案例的 `primary_family` 是 `workspace_rubric_grounding`；
2. 哪些案例把 grounding 列入 `acceptable_families`；
3. A、B、A∪B 在两种 family 口径下的 routing recall；
4. 旧的 30 条混合分母中有多少属于其他 detector family。

## 2. 冻结输入

- holdout manifest：
  `experiments/workspace_grounding/DUAL_TRIAGE_HOLDOUT_30_20260728.json`
- dual-triage result：
  `reports/workspace_grounding_dual_triage_holdout30_20260728/grounding_dual_triage_items.jsonl`
- reviewed reference：
  `WorkspaceBench_full388_Codex证据化逐条标注_20260720.md`
- dataset：
  `datasets/workspacebench/full.jsonl`

输入文件 SHA256、盲包 SHA256 和 sealed mapping SHA256 必须记录在 receipt。

## 3. 样本与盲法

- 纳入 holdout 中全部 30 条 `较可信真问题`；
- 不抽样，不增加阴性对照；
- blind package 不包含 item id、reviewed label、A/B/union 路由状态、verifier
  verdict 或 source stratum；
- 模型只看到 task、output contract、允许输入证据和 rubric；
- 每个 task 使用全新 API 请求；
- 模型冻结为 `google/gemini-3.1-pro-preview`；
- sealed mapping 在独立标注、校验和回执提交前不得揭示。

本轮选择集本身来自 reviewed-positive，因此它不能用于重新估计缺陷 prevalence
或 detector precision；它只用于责任边界和 routing recall。

## 4. 标签

沿用 P0 全部字段与判定边界。family 定义进一步冻结为：

- `workspace_rubric_grounding`：rubric requirement 是否被 task/input 合理支持；
- `task_contract`：task、output contract、文件名、交付形式或内部契约冲突；
- `artifact_execution`：requirement 合法，但满足性需打开/执行 artifact；
- `input_recomputation`：需从输入重算数值、表格或约束；
- `subjective_quality_review`：清晰度、专业性、视觉质量等主观要求；
- `unknown`：现有证据不能稳定归属。

`primary_family` 表示主要责任；`acceptable_families` 表示任何一个发现该根因都
可计为合法命中。不能为了提高某个 router 的 recall 把 grounding 无条件加入
acceptable set。

## 5. 指标

分别计算：

1. `primary-grounding recall`：
   分母为独立模型判定 `is_grounding_defect=yes` 且
   `primary_family=workspace_rubric_grounding`；
2. `acceptable-grounding recall`：
   分母为 `is_grounding_defect=yes` 且 grounding 出现在
   `primary_family/acceptable_families`；
3. coverage：30 条中独立模型 yes/no/uncertain 的数量；
4. A、B、A∪B 的 hits、FN 和逐例清单；
5. 与 P0 四条重复案例的一致性，作为确定性复跑检查。

若独立模型否定某条旧 reviewed-positive，该案例从 family recall 分母中排除，
但必须单独报告，不能静默删除。

## 6. 解释边界

- 本轮仍是 model-reviewed reference，不是 human gold；
- 不用 P1 调整 prompt/router 后在同一 30 条上重新声明泛化提升；
- 完成 P1 后，该 holdout 只能用于诊断和 contract 开发；
- 下一版方法的最终结果必须来自第三份 task-disjoint holdout。
