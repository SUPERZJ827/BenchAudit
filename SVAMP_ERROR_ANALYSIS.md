# SVAMP-Platinum 逐题误差分析

## 分析口径与分类结果

本次分析使用固定 manifest 中的 100 道题，并以 `metadata.audit_label` 作为参考标签。

需要注意的是，BenchAudit 输出的 `candidate` 和 `review` 仅表示“值得进一步检查”，并不代表系统已经自动确认题目存在错误。

两种方法的结果差异如下：

- BenchAudit 比单次 LLM **多发现 8 道已知缺陷题**；
- 有 **4 道题**被单次 LLM 找到，但被 BenchAudit 漏掉；
- BenchAudit 将 **18 道 clean 标签题目**标记为候选问题；
- 单次 LLM 将 **15 道 clean 标签题目**标记为候选问题；
- 两种方法共同漏掉了 **2 道已知缺陷题**。

这里暂时将“数据集标为 clean、但系统报告为候选”的题目记为 FP。不过，这只是基于现有 Platinum 标签的评估结果，并不意味着这些题目一定没有问题。后续仍需结合题目内容和系统证据逐条判断，也不会在本轮分析中修改原始标签。

最突出的三个方向是：

1. **多个 auditor 重复同一根因**：同一题可能同时由 question、quantity、event 或 gold 报告，候选级指标虽按 item 去重，但 review 噪声和证据膨胀仍然存在。
2. **标准模板措辞被判歧义**：模型对小学应用题的常规省略和模板表达要求过严，在没有第二个同等自然答案时仍报告 ambiguity。
3. **答案字段/程序化求值自相矛盾**：若干响应的 rationale 和算式给出正确答案，但 `derived_answers` 填入中间量或错误值，程序化 gold 比较随后产生高置信 FP。

## G. 下一轮优先改进建议

**优先增加结构化响应的一致性校验**

目前，系统在使用 `derived_answers` 与标准答案 `gold` 进行比较或聚合前，没有检查 `derived_answers`、最终算式、`checks` 和 `rationale` 是否相互一致。因此，当 LLM 返回的各字段互相矛盾时，系统仍可能将该题标记为 `candidate`，从而产生误报。

建议在结构化结果进入后续判断前增加校验：

- 各字段一致时，继续比较和聚合；
- 各字段不一致时，将本次响应视为无效并重试；
- 多次重试仍不一致时，降级为 `unknown`，不生成 `candidate`。

该问题在题目 `162、599、687、934、974` 中重复出现，适合将这些样例编写为固定回归测试。修改范围主要集中在结构化结果校验层，影响较小，也不会像简单提高判定阈值那样，以牺牲 Recall 为代价减少误报。

## H. 数据格式与完整性检查

两种实验输出的 `comparison` 文件结构不同：

- 在单次 LLM 基线中，`candidate.prediction_items` 直接保存被判定为问题的题目 ID。
- 在 BenchAudit 中，同名字段保存的是候选题目数量，具体题目 ID 需要从 `candidate_ranking` 或 `candidate_risk_scores` 中读取。
- 本次分析脚本已经兼容这两种格式。

此外，BenchAudit 中同一道题可能同时触发多个 `violation`。为避免重复统计，候选题目数量统一按照 **item ID 去重** 后计算。

数据完整性检查未发现异常：

- manifest 中没有重复题目；
- 实验结果中没有缺失题目；
- 缓存中没有空响应。
