# 1. 新结果：缺陷不改排名，但系统性扭曲分数

## 1.1 先说旧结论为什么是 null

我们此前的排名影响实验用的是**删题**——把缺陷题从 1000 题里剔除后重算榜单。结果：

| 剔除依据 | 全局 Kendall τ | 最大名次变动 | Top-1 |
|---|---:|---:|---|
| 第三方标注（181 题） | 0.981 | 1 | 未变 |
| 我们审计器检出（318 题） | 0.981 | 1 | 未变 |

per-subject 冠军易主 9/28，但**随机删等量题的对照显示无统计差异（p ≈ 0.32）**。

**删题是最弱的扰动**：所有模型同步失去同一批题，分母一起缩小，相对序几乎不动。

## 1.2 改用强扰动：改正 gold 后重新评分

MMLU-Redux 带 `verified_gold` 字段。在排名实验用的这 1000 题里，**101 题的更正答案与原 gold 不同**。用 15 个模型已有的作答重新评分（零成本、纯离线）：

| 模型 | 原始 acc | 改正后 acc | Δ |
|---|---:|---:|---:|
| deepseek | 0.803 | 0.867 | **+0.064** |
| google/gemini-2.5-flash | 0.770 | 0.830 | +0.060 |
| openai/gpt-4o | 0.745 | 0.800 | +0.055 |
| meta-llama/llama-3.3-70b | 0.689 | 0.744 | +0.055 |
| … | | | |
| meta-llama/llama-3.1-8b | 0.593 | 0.629 | +0.036 |
| mistralai/mistral-nemo | 0.582 | 0.616 | **+0.033** |

**排名依然几乎不动**：Kendall τ = 0.981，最大名次变动 1 位，Top-1 未变，15 个模型里只有 2 个名次有变化。

## 1.3 但分数层面的结论很强

| 量 | 值 |
|---|---:|
| 最强模型被**低估** | **6.4 个百分点** |
| 修正量范围 | +0.033 ~ +0.064 |
| **修正量跨度（不是常数偏移！）** | **0.031** |
| 两两对比中，原始分差 **小于** 该跨度的 | **28 / 105 = 27%** |
| 两两分差的**平均相对变化** | **18.9%** |
| 单对分差最大变化 | +0.031（相对 +20%） |

分差变化最大的几对：

```
deepseek vs qwen-2.5-7b          0.169 → 0.200   (+18%)
deepseek vs mistral-nemo         0.221 → 0.251   (+14%)
deepseek vs command-r            0.165 → 0.194   (+18%)
qwen-2.5-7b vs gemini-2.5-flash  0.136 → 0.163   (+20%)
```

## 1.4 这意味着什么

> **Benchmark 缺陷不会打乱排行榜，它会系统性压缩并扭曲分数——而且对更强的模型压得更狠。**

机制是清楚的：在 gold 错误的题上，**更强的模型更可能给出真正正确的答案**，因而被错判为答错；修正后它们获得更大的回补。原始榜单实际上在**奖励"和标注者犯同样的错误"**。

三条可直接写进论文的推论：

1. **缺陷不是常数偏移，不会"相互抵消"。** 跨度 0.031 意味着任何"模型 A 比 B 强 3 个百分点"的结论都落在这层测量误差里；
2. **27% 的两两对比不可靠**——这些对的原始分差比缺陷引起的误差还小；
3. **效应量被系统性低估**：两两分差平均被压缩 18.9%。

**这比"排名会变"是更好的结果**：它反直觉、可量化、而且直接影响所有引用 MMLU 数字做模型比较的工作。**而且完全不依赖被卡住的执行环境。**

# 2. 距离 ICLR 还差什么

## 2.1 现在手里有什么（按可发表强度排序）

| 资产 | 状态 | 独特性 |
|---|---|---|
| **审计器仪器不稳定性** | SVAMP n=5 + MMLU 清洁对，机制定位到 prompt 级联 | **文献里没人报过** |
| **分数扭曲量化**（§1） | 刚跑出来，零成本 | 反直觉，比"排名变化"强 |
| 确定性层 vs LLM 层复现率完全分离 | 1.00 vs 0.68–0.90，三次独立复制 | 把设计信条变成实测 |
| 分层证据架构 + 硬天花板 | 代码 + 对抗测试全过 | 系统贡献 |
| 检测性能 | MMLU 上 recall 0.76 / precision 0.43（对第三方标注） | 中等 |
| 诚实负结果 | 2.49% 预飞、0/0 链路、5×NOT_IDENTIFIABLE | 方法论加分 |

## 2.2 缺什么（按阻塞程度排序）

### G1｜方法贡献目前不可证伪 —— **最致命**

当前模型下 BenchCore vs Naive LLM：**+0.021 F1**，而同代码 5 次重复的 F1 极差是 **0.046**。差值落在噪声内。

**审稿人会问："你的结构化分解真的比直接问一次 LLM 强吗？"现在我们答不上来。**

召回上 +0.131 看起来是真的（naive 的 0.632 低于我们 5 次全部），但**没有做每臂多次**，所以严格说也只是一次观测对一次观测。

### G2｜确认层没有分母

注入召回只在 DS-1000 上做过 3 类缺陷（20/20、20/20、13/20）。没有**协议 × 缺陷类**的矩阵，就无法回答"这套确认合同能抓住多少比例的评分器缺陷"。

### G3｜影响结论只有一个 benchmark family

§1 的结果只在 MMLU-Redux 上。SVAMP-Platinum 和 GSM8K-Platinum 都有人工标注，**可以立刻做同样的分析**。

更重要的是缺**第二种干预类型**：MMLU 是"改标签"，而文献里效应最大的是"**改评分器**"（STING 报告增强测试让 top-10 修复 agent 的 resolved rate 掉 4.2–9.0%）。我们有 DS-1000 的两条真评分器缺陷，但修复闭环没做。

### G4｜缺少审稿人一定会问的基线

现有基线：rules-only、naive LLM、LLM+分类法。**缺**：

- **多模型共识/分歧**——MMLU-Redux 和 Platinum Benchmarks 都用这个，不放会被直接质疑；
- **响应模式/IRT 排序**——2026 年有专门论文用 114 个模型拟合 item 指标；
- **人工/专家复核上界**——所有对比都是自动方法对自动方法，没有天花板参照。

### G5｜没有任何一次修复闭环

从 confirmed（或 review）到"最小修复 → 同一证明变 clean → 零回归 → 重新评分"，一次都没跑通。

### G6｜统计处理不达标

按我们自己测出来的噪声水平，**论文里任何 n=1 的比较都会被自己的发现打脸**。所有主表必须 n≥3 并给区间。

## 2.3 我建议砍掉的

**可信裁决器 / 生产 Git verifier / APPS 双正例这条线，不要作为论文的必要组成。**

它卡在执行环境（本宿主无直接出口，双引擎拓扑均失败），而且**§1 已经证明论文的核心叙事根本不需要它**。把它写成一个 system section（"我们建了什么、为什么某些主张必须封顶在 review"），不要让投稿时间表挂在它上面。

# 3. 论文该讲什么（重写后的主张）

> **Benchmark 审计的难点不在发现缺陷，而在两件被忽略的事：审计器自己是不稳定的测量仪器，以及缺陷的真实危害不在排行榜而在分数。**
>
> 我们给出：(a) 首次量化自动 benchmark 审计器的运行间复现性——同代码同配置下逐条 finding 复现率 0.68–0.90，而确定性组件为 1.00，并把机制定位到答案依赖的 prompt 级联；(b) 一套分层证据架构，用硬天花板阻止模型判断污染可确认结论，全部对抗控制 fail-closed；(c) 证明 benchmark 缺陷不重排榜单却系统性扭曲分数——最强模型被低估 6.4 个百分点，27% 的两两模型对比落在缺陷引起的测量误差之内，两两分差平均被压缩 18.9%。

三个贡献互相咬合：(a) 说明为什么检测数字不能单跑比较；(b) 说明怎么在不稳定的组件上仍然给出可信结论；(c) 说明为什么这件事值得做。

**全部不依赖被卡住的执行环境。**

# 4. 给 GPT 的规划

## P1（最高优先）：把方法贡献变成可证伪的 —— 四臂 × n≥3

**已冻结的三臂消融要扩成四臂**，加入 **Naive LLM** 臂。这是唯一能回答 G1 的实验。

| 臂 | 定义 |
|---|---|
| A. Naive LLM | 单次提问，无分解、无分类法 |
| B. 当前 BenchCore | 现状 |
| C. 收紧触发 | 主靶 `llm_gold_audit`（复现率 0.68，两个 benchmark 一致最差） |
| D. gold-only vote-3 | 只对 `llm_gold_audit` 投票 |

要求：

- **每臂 ≥3 次独立运行，全新缓存**；
- 报告 **min / median / max + 逐条复现率**，不报点值；
- 主判据：**臂间差异是否超出臂内跨度**。超不出就如实写"不可归因"；
- 数据集：SVAMP-100 先做（便宜），MMLU-200 跟进；
- 启动前做**零 API 调用量预飞**，用实测调用数定预算，不要沿用任何估算。

**这个实验的结果决定论文的方法贡献能不能立住。如果 B 相对 A 的优势在 F1 上确实不显著，就诚实地把主张收缩为"显著提高召回"，并把这一点本身当作发现写出来。**

## P2：把 §1 的分数扭曲结果做扎实（新的论文头条）

§1 是我在这次对话里临时跑的，**不是冻结实验**。要做成论文级：

1. **冻协议再重跑**（输入哈希、manifest、评分口径、bootstrap 次数全部写死）；
2. **加区间**：对每个模型的 Δacc、每对的分差变化做 bootstrap（按题重抽样，≥1000 次），给 95% CI；
3. **扩到第二、第三个 benchmark**：SVAMP-Platinum、GSM8K-Platinum 都有人工标注，同样算"改正后重评"；
4. **加闭环版本**：除了用第三方 `verified_gold`，再算一版**用我们自己审计器检出的题 + 我们自己提出的更正答案**。两版并列报告：
   - 第三方版 = "一个完美审计器能带来多大修正"（上界）；
   - 自检版 = "我们的系统端到端能带来多大修正"（review 级，必须标注）；
   - **两者的差距本身就是一个指标**。
5. **明确报告"排名不变"这个负结果**，不要藏——它正是让"分数扭曲"这个正结果显得反直觉的对照。

**产出**：一张主表（每 benchmark × 每模型的低估幅度 + CI）、一张两两对比表（多少比例落在测量误差内）、一句 headline 数字。

## P3：确认层的分母 —— 协议 × 缺陷类矩阵

把 `scripts/run_ds1000_defect_injection.py` 里的三个算子提升为 `benchcore` 中协议无关的组件，在 ≥3 个执行协议上跑，产出：

```
            neutralize_comparator   reject_gold   implementation_assert   …
DS-1000            20/20              20/20            13/20
APPS               ?                    ?                ?
第三个协议          ?                    ?                ?
```

每格必须配一个**合法对照集上的假阳数**（必须为 0），否则"零假阳"能被一个什么都不确认的系统满足。

**这是文献里没有的东西**：所有人报 precision@k，没人报确认层的召回，因为没有分母——而注入给了我们一个合法分母。

## P4：补齐审稿人一定会问的基线

1. **多模型共识**：用 ≥3 个不同家族的模型，取一致/分歧作为候选信号。MMLU-Redux 和 Platinum 都用这个方法，不放会被直接质疑；
2. **响应模式排序**：我们有 15 个模型在 1000 题上的完整作答（`reports/ranking_impact/answers/`），**可以离线零成本**算出"多少强模型给出同一非 gold 答案"这类信号，做成一个纯统计基线；
3. **人工上界**：用 Platinum/Redux 的人工标注作为参照点，说明自动方法离人工还有多远。

第 2 条尤其值得优先——**零 API、数据现成**，而且它是最强的非 LLM 基线。

## P5：修复闭环（唯一还需要挑目标的一项）

原计划的 DS-1000 id=300 挂在裁决器上。**建议改用不依赖执行环境的目标**：

- MMLU-Redux 中我们检出且第三方也标注为 `wrong_groundtruth` 的题（交集 138 条）——修复 = 用更正答案替换，验证 = 同一检查器不再报警 + 全量回归无新增 finding + 重新评分给出 §1 那套指标；
- 这条闭环**完全离线可做**，而且直接接到 P2 的产出上。

不要等裁决器。

## P6：论文写作层面的硬约束

- 主表任何数字必须标 **n**；n=1 的一律标注"不可归因"；
- Workspace 的 1940/1940 **不能写成"召回 100%"**，必须写成"五个自设计确定性算子的一致性结果"；
- 通用层在真实未修改数据上的 confirmed 是 **0**，这一点要在 limitations 里明写，不要靠 benchmark 专用检查器的数字撑场面；
- 排名不变这个负结果要主动写出来。

# 6. 一句话回答用户的问题

> **"假设检出的都是真错误，影响有多大？"——排名上几乎没有影响（τ=0.981，我们用删题和改正重评两种扰动各验证了一次）；但分数上影响很大：最强模型被低估 6.4 个百分点，27% 的两两模型对比落在缺陷引起的测量误差之内，两两分差平均被压缩 18.9%。**
>
> **这才是这个课题的 so-what，而且它完全不依赖我们现在卡住的那条执行环境的路。**
