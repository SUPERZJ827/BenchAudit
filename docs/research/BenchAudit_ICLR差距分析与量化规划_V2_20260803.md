# 0. V1 的错误清单（先认账）

| V1 的说法 | 实际 | 判定 |
|---|---|---|
| "两两分差**平均被压缩 18.9%**" | 18.9% 是**绝对**相对变化，混入了 20 对缩小的；有符号均值是 **+11.9%** | **表述错误** |
| "**27%** 的两两对比不可靠" | 用**全局跨度 0.031** 当作每一对的阈值。每对该看的是该对自己的 \|Δ_a − Δ_b\| 加区间。全局跨度只能做**敏感性筛选**，不能宣布不可靠 | **统计错误** |
| "我们检出且第三方标注为 wrong_groundtruth 的题（交集 **138** 条）" | 138 是**三类客观缺陷的整体交集**。wrong_groundtruth 真值是 **106** 条 | **口径错误** |
| "扩到 SVAMP-Platinum、GSM8K-Platinum，成本 **¥0**" | 那两个数据集**没有 15 模型作答矩阵**，不重跑模型就算不出分数影响 | **可行性错误** |
| "这比'排名会变'是更好的结果……文献里没人报过" | MMLU-Redux 原文摘要即写 *"demonstrate significant discrepancies with the model performance metrics that were originally reported"* | **新颖性误判** |
| P1 判据"臂间差异 > 臂内跨度" | 不充分：还需等预算、配对设计、item 层 cluster bootstrap、n≥5 | **设计不足** |

以上更正由 GPT 提出，我用冻结的 1000 题与 15 份模型作答独立重算，**数值全部复现**（个别小数差异来自分母口径，非分歧）。

**V1 还漏掉了一个比上述任何一条都致命的问题——盲测/选择偏差，见 §3.1。**

# 1. 更正后的分数影响结果

## 1.1 实验

MMLU-Redux 带 `verified_gold`。排名实验用的 1000 题里 **101 题**的更正答案与原 gold 不同。用 15 个模型已有的作答重新评分（纯离线）。

## 1.2 排名层面：两种扰动都是 null

| 扰动 | 全局 Kendall τ | 最大名次变动 | Top-1 |
|---|---:|---:|---|
| 删除缺陷题（181 / 318 条） | 0.981 | 1 | 未变 |
| **改正 gold 后重评（101 条）** | **0.981** | **1** | **未变** |

15 个模型里只有 2 个名次有变化。per-subject 冠军易主经随机删题对照后 p ≈ 0.32，不显著。

**结论：在 MMLU-Redux + 15 模型这个设置下，benchmark 缺陷不改变排行榜。弱扰动（删题）和强扰动（改正重评）各验证一次。**

## 1.3 分数层面：可守住的表述

| 量 | 值 | 边界 |
|---|---:|---|
| 各模型 acc 修正量 | +0.033 ~ **+0.064** | 全部为正 |
| 最强模型被低估 | **6.4 个百分点** | 单点估计，尚无 CI |
| 105 个模型对中，修正后**差距扩大** | **84** | |
| 差距**缩小** | 20 | |
| 幅度不变 | 1 | |
| **顺序翻转** | **1** | |
| 两两分差**有符号**平均相对变化 | **+11.9%** | 正=差距扩大 |
| 两两分差**绝对**平均相对变化 | 18.9% | 仅供参考，不作主张 |
| Spearman(原始 acc, 修正增益) | **0.796** | **n=15 且模型不独立，需预注册检验** |

**能守住的一句话**：

> 错误 gold **通常压缩模型间差距**（105 对中 84 对在修正后扩大），并**对高分模型造成更大低估**（增益 +0.033→+0.064，与原始准确率的 Spearman ρ≈0.80，n=15，非独立样本）。

**不能说的**：

- ❌ "27% 的对比不可靠"——需逐对算 \|Δ_a − Δ_b\| 并给区间；
- ❌ "平均压缩 18.9%"——混淆了有符号与绝对；
- ❌ "文献里没人报过"——见 §2。

# 3. ICLR 缺口（重排后）

## 3.1 G0（新增，最高优先）：没有真正的盲测 —— 比 V1 列的任何一条都致命

SVAMP-100 与 MMLU-1000 已被 A/A′/A″ 路由、阈值调整、prompt 精修、多轮消融**反复使用**。即使接下来每臂跑五次，也只能证明**这些数据上的重复性**，不能证明泛化。

这是典型的 dev-set 过拟合，而我们在这两个集上迭代的轮数特别多。

**要求**：冻结最终方法 → 一个未参与设计的 holdout → **在看标签前**冻结阈值与指标 → 最好由未看过开发结论的人做盲审。

### 现成的最优解

| 层 | 集合 | 规模 | 用途 |
|---|---|---:|---|
| 同分布 holdout | MMLU-Redux **从未参与任何实验**的部分 | **4,613 / 5,700** | 阈值与测量类主张 |
| 跨 family holdout | 另选一个从未碰过的 benchmark | 待定 | 泛化主张 |

（清点：5700 题中被 `pilot1000` + `pilot200` + `diag8` 用过的共 1,087 条。）

同分布 holdout 不能替代跨 family，但它能**立刻**守住"阈值是在看标签前冻的"。

## 3.2 G0 威胁不到什么 —— 这正是主线该选测量研究的理由

**复现性是仪器的属性，不是泛化性能。** 在被用过的数据上测 run-to-run 方差完全合法——估的是测量噪声，不是外推能力。

| 受 G0 威胁 | 不受威胁 |
|---|---|
| 检测 P/R/F1 | 仪器稳定性（SVAMP n=5、MMLU 清洁对） |
| 阈值选择 | 确定性层 1.00 vs LLM 层 0.68–0.90 |
| 消融结论 | prompt 级联机制 |

**核心现象免疫于最致命的批评**——这不只是"更安全"，是主线选择的实质理由。

## 3.3 其余缺口（V1 中判断正确的部分）

- **G1｜方法贡献不可证伪**：BenchCore vs Naive 是 +0.021 F1，而同代码 5 次重复极差 0.046。差值落在噪声内；
- **G2｜确认层无分母**：注入召回只有 DS-1000 三类；
- **G3｜影响结论单一 benchmark**：且扩展受限于模型作答矩阵可得性（见 §0）；
- **G4｜缺基线**：多模型共识、响应模式/IRT 排序、人工上界；
- **G5｜零修复闭环**；
- **G6｜主结果大量 n=1**。

## 3.4 退出关键路径

可信裁决器 / 生产 Git verifier / APPS 双正例 —— 卡在执行环境，且主线不依赖。写成 system section，不作为投稿依赖。

多协议注入矩阵（原 P3）同样退出关键路径。

# 4. 论文主线（改为测量研究）

> **LLM benchmark auditor 本身是不稳定的测量仪器：聚合 F1 可以看似稳定，而逐条 finding 大幅翻转。我们量化这种不稳定性、定位其级联放大机制，并研究它如何传导进缺陷率与分数影响的估计。确定性证据层提供稳定对照与安全边界。**

三部分真正统一：

1. **审计器稳定性**——同代码同配置，SVAMP violation-Jaccard 0.845（n=5，10 对），MMLU 0.683（清洁对）；确定性组件 1.00，LLM 组件 0.68–0.90（三次独立复制）；
2. **prompt 级联的因果消融**——见 §5.3，这是因果核心；
3. **对下游估计的传导**——不稳定的检测如何让缺陷率与分数影响估计本身带上误差棒。

**证据天花板作为设计原则与安全保障出现，不与前两项并列成第三个巨型贡献。**

若坚持"系统论文"路线，则通用层真实数据 confirmed=0、无盲测、无修复闭环仍是硬伤，必须先重新激活自然缺陷确认路径。

# 5. 给 GPT 的规划

## 5.1 P0：更正并预注册 §1 的统计口径

- 出脚本 + receipt + 输入哈希，冻结评分口径；
- **逐对**计算 \|Δ_a − Δ_b\| 而非用全局跨度；
- 按**题**做 cluster bootstrap（≥1000 次）给每个 Δacc 与每对分差变化的 95% CI；
- 顺序翻转（当前 1/105）单独报告；
- Spearman 检验必须**预注册**，并明写 n=15 且模型不独立；
- **主动报告"排名不变"这个负结果**，它是让分数结论显得反直觉的对照。

## 5.2 P1：冻结盲测集

1. 从 MMLU-Redux 未使用的 4,613 条中按 subject 分层抽样，冻结 manifest（含 `source_sha256`、seed、item ID）；
2. **在冻结之前不得查看这些题的任何标签或运行任何检测**；
3. 同时选定一个跨 family 的 holdout benchmark，做**数据可得性预飞**（有无缺陷标签、有无模型作答矩阵）；
4. 冻结所有阈值与指标定义，提交后才允许跑。

## 5.3 P2：级联切断的因果消融 —— **主线的因果核心，从第 5 位提到第 3 位**

因果主张是"答案依赖的 prompt 级联把 temp-0 抖动放大成逐条翻搅"。**要验证它必须做干预，不是再加一个对比臂。**

| 臂 | 干预 |
|---|---|
| 基线 | 现状（`blind_solution` 自由文本嵌入下游 prompt） |
| **切断-1** | 把嵌入下游的 `blind_solution` 换成**规范化结构摘要**（杀掉自由文本信道） |
| **切断-2** | 让 `blind_solution_is_risky()` / `defender_is_needed()` 等门控变确定性 |
| 切断-1+2 | 两者同时 |

**预注册预测**：复现率朝确定性层的 1.00 上移。**若不上移，机制主张即被证伪**——这一点必须在跑之前写进协议。

指标：violation-Jaccard、item-Jaccard、缓存键重合率（当前 60%，是扇出的直接度量）、以及**召回是否因此下降**（切断级联可能同时削掉覆盖，这个代价必须报告）。

大部分可用已有缓存 + 确定性改造离线完成。

## 5.4 P3：15 模型响应模式 / IRT 基线（零 API，数据现成）

`reports/ranking_impact/answers/` 有 15 个模型 × 1000 题的完整作答。可离线算：

- "多少强模型给出同一非 gold 答案"类共识信号；
- item 难度 / 区分度的心理测量拟合；
- 与我们的 LLM 审计器在同一真值上比 P/R/F1。

**这是最强的非 LLM 基线，而且零成本。** MMLU-Redux 与 Platinum 都用这类方法，不放会被直接质疑。

## 5.5 P4：Naive vs BenchCore，等预算配对 n≥5

修正 V1 的设计缺陷：

- **等预算**，或至少同时报告调用量 / token / 成本 / 延迟（vote-3 用 3× 调用，不控预算等于偷跑）；
- **配对运行设计**（同一批种子/顺序下成对比较）；
- **item 层 cluster bootstrap** 给区间；
- **n≥5**，不止 min/median/max；
- 四臂：Naive / 当前 BenchCore / 收紧触发（主靶 `llm_gold_audit`）/ gold-only vote-3；
- 启动前做**零 API 调用量预飞**定预算。

**若 F1 优势仍不显著，就诚实收缩为"显著提高召回"，并把这一点本身当作发现写出来。**

## 5.6 P5：一条真实修复闭环

目标改为 **MMLU-Redux 中 `wrong_groundtruth` 的 106 条**（不是 V1 写的 138）。

链条：我们检出 → 提出更正答案 → 与 `verified_gold` 比对 → 重评分 → 全量回归无新增 finding。

**GPT 重算的链条（我未独立验证，需复核）**：106 条中约 95 条有任意 finding、约 70 条系统给出唯一更正答案、**仅 61 条与 `verified_gold` 一致**。

这个"61/106"本身就是一个诚实且有信息量的指标：**端到端自动修复的正确率**。

## 5.7 P6：跨 benchmark 扩展前先做可得性预飞

SVAMP-Platinum / GSM8K-Platinum 有 gold 修正（38 / 10 条）但**没有模型作答矩阵**。扩展前必须先回答：能否拿到或负担得起重跑多模型作答。不要按 ¥0 规划。

# 8. 总判断

> 现在已经有一篇有潜力的 ICLR empirical paper 的**核心现象**（审计器是不稳定的测量仪器，且这种不稳定性会传导进所有下游估计），但**还没有 ICLR 级的证据包**。
>
> 主要短板不是"系统功能不够多"，而是"主张是否被实验充分支持"——具体就是：无盲测、n=1 比较、方法增益落在噪声内、无修复闭环。
